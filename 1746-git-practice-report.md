# Работа в системе контроля версий (на примере Git)

**МДК 02.02 · группа 3424А**
**Репозиторий:** [github.com/Ilmir307/git-practice](https://github.com/Ilmir307/git-practice)

## 1. Цель работы

Ознакомиться с основами работы в системе контроля версий Git и практически применить её функции: создание репозитория, работа с файлами, ветвление и слияние.

## 2. Выполненные шаги

1. **Создание репозитория.** Локально: `git init -b main`; удалённый репозиторий `git-practice` создан на GitHub и связан с локальным.
2. **Добавление файлов.** Добавлены `utils.py` и `notes.txt`: `git add .` → `git commit -m "Добавлены utils.py и notes.txt"`.
3. **Внесение изменений.** В `utils.py` добавлена функция `farewell`, создан новый файл `config.py`, ненужный файл удалён: `git rm notes.txt` → `git add .` → `git commit`.
4. **Создание ветки.** `git branch feature-greeting` и переключение `git checkout feature-greeting` (либо одной командой `git checkout -b`).
5. **Изменения в ветке.** Файл `utils.py` оформлен по PEP 8 (docstring, защита `__main__`), изменения зафиксированы коммитом в ветке.
6. **Отправка на сервер.** `git push -u origin feature-greeting` — ветка отправлена в удалённый репозиторий.
7. **Слияние.** Возврат в основную ветку `git checkout main` и слияние `git merge --no-ff feature-greeting` — изменения из ветки перенесены в main отдельным merge-коммитом.
8. **Удаление ветки.** `git branch -d feature-greeting` — отработанная ветка удалена; финальное состояние отправлено на GitHub командой `git push`.

## 3. Результаты (история репозитория)

```text
*   d9acfa0 Слияние ветки feature-greeting в main
|\
| * faa09c8 Ветка feature-greeting: utils.py оформлен с docstring и __main__
|/
* aa6de89 Добавлены farewell и config.py, удалён черновик notes.txt
* 9924db5 Добавлены utils.py и notes.txt
```

Граф истории показывает характерную «петлю»: ветка отделилась от main, получила свой коммит и вернулась слиянием. Команда `git status` на каждом этапе подтверждала чистое состояние рабочего дерева после коммитов. Программа после слияния запускается и выводит приветствие и прощание.

## 4. Вывод

Освоен полный рабочий цикл Git: инициализация репозитория, фиксация изменений (`add`/`commit`), добавление и удаление файлов (`git rm`), отправка на GitHub (`push`), ветвление (`branch`/`checkout`), слияние (`merge`) и удаление отработанной ветки (`branch -d`). Ветвление позволяет вести доработку изолированно от стабильной версии, а история коммитов сохраняет весь путь изменений.
