# Анализ производительности и поиск утечек памяти с использованием Valgrind и gcov

**МДК 02.02 · группа 3424А**

## 1. Цель работы

Изучить инструменты Valgrind и gcov для анализа производительности и поиска утечек памяти; выявить и устранить проблемы в предоставленной программе на Python.

## 2. Примечание об инструментах

Valgrind и gcov — инструменты для программ на C/C++ под Linux: Valgrind анализирует работу с памятью машинного кода, gcov — покрытие скомпилированного кода. Для программы на **Python под Windows** они неприменимы напрямую, поэтому использованы их функциональные аналоги из экосистемы Python: **tracemalloc** (стандартная библиотека, учёт выделенной памяти) и **coverage** (покрытие кода при выполнении, аналог gcov). Методика анализа — та же: замер → выявление проблем → исправление → контрольный замер.

**Анализируемая программа:** [task1740_leaky.py](task1740_leaky.py) — поиск повторяющихся слов в списке; содержит три проблемы: вложенный цикл O(n²), лишние копии строк в памяти, мёртвая функция. Замеры выполняет [task1740_measure.py](task1740_measure.py) на списке из 5000 слов.

## 3. Первичный анализ (выдержки из отчётов)

Замер времени (time.perf_counter) и пиковой памяти (tracemalloc):

```text
Слов в списке: 5000
find_duplicates_leaky:
  дублей найдено: 499
  время: 12.85 с
  пиковая память: 321.3 КБ
```

Покрытие кода (coverage, аналог gcov):

```text
Name                    Stmts   Miss  Cover   Missing
task1740_leaky.py          14      2    86%   29-30
```

**Выявленные проблемы:**

1. Время 12,85 с на 5000 слов — квадратичный алгоритм O(n²): каждое слово сравнивается с каждым.
2. Пиковая память 321,3 КБ — список `copies` хранит удвоенные копии всех строк.
3. Покрытие 86 % — функция `dead_code` (строки 29–30) никогда не выполняется: мёртвый код.

## 4. Внесённые изменения

Файл [task1740_optimized.py](task1740_optimized.py):

1. Вложенный цикл заменён на два множества (`seen`, `duplicates`) — сложность O(n): каждое слово обрабатывается один раз.
2. Лишние копии строк убраны — память не расходуется на дублирование данных.
3. Мёртвая функция удалена — код не несёт непокрываемых участков.

## 5. Контрольный замер после оптимизации

```text
find_duplicates:
  дублей найдено: 499
  время: 0.0 с
  пиковая память: 168.5 КБ

task1740_optimized.py       8      0   100%
```

| Метрика | До | После | Улучшение |
|---|---|---|---|
| Время на 5000 слов | 12,85 с | < 0,001 с | более чем в 12 000 раз |
| Пиковая память | 321,3 КБ | 168,5 КБ | в 1,9 раза |
| Покрытие кода | 86 % | 100 % | мёртвый код устранён |

Корректность сохранена: обе версии находят одинаковое число дублей (499).

## 6. Выводы

Применена методика анализа в стиле Valgrind/gcov средствами Python: замер памяти (tracemalloc) и времени, анализ покрытия (coverage). Выявлены и устранены три дефекта: квадратичная сложность алгоритма, избыточное потребление памяти и мёртвый код. Результат: ускорение на четыре порядка, почти двукратное снижение пиковой памяти и покрытие 100 %. Вывод инструментальный: анализ покрытия нужен не только тестам — он же выявляет ненужный код, а замеры «до/после» превращают оптимизацию из гадания в проверяемую гипотезу.
