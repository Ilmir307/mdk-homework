# Анализ и стандартизация требований к программному обеспечению

**Проект: ПО для автоматизации бизнес-процессов компании · МДК 02.02 · группа 3424А**

## 1. Цель работы

Изучить основные понятия и стандарты, применяемые при разработке требований к программному обеспечению; научиться анализировать и стандартизировать требования в соответствии с заданными критериями.

**Объект анализа** — программное обеспечение для автоматизации бизнес-процессов компании: учёт сотрудников, постановка и согласование заявок, документооборот, отчётность для руководства.

## 2. Выбранные стандарты и обоснование выбора

| Стандарт / модель | Для чего используется в работе | Обоснование выбора |
|---|---|---|
| ISO/IEC/IEEE 29148 | Форма записи требований (однозначность, полнота, проверяемость) | Международный эталон инженерии требований: даёт критерии «хорошего» требования |
| ГОСТ Р ИСО/МЭК 25010-2015 | Проверка полноты нефункциональных характеристик | Действующий российский стандарт качества ПО, обязателен при работе по ГОСТ |
| Модель FURPS+ | Классификация требований по шести группам | Простой чек-лист: быстро показывает, какие категории забыты в исходном списке |

Метод анализа: каждое исходное требование относится к функциональному блоку системы и к компоненту FURPS+; затем переформулируется по критериям ISO/IEC/IEEE 29148 (однозначность, проверяемость, полнота); полнота покрытия сверяется по ГОСТ Р ИСО/МЭК 25010-2015.

## 3. Анализ исходных требований

Исходные требования получены в виде списка пунктов в свободной форме:

1. Система должна хранить данные сотрудников.
2. Нужно быстро находить документы.
3. Руководитель должен видеть, кто чем занят.
4. Заявки должны согласовываться по цепочке.
5. Система не должна тормозить.
6. Нужны отчёты за любой период.
7. Доступ только для своих.
8. Интерфейс должен быть удобным.

**Выделенные функциональные блоки системы:**

- **Б1. Управление пользователями и доступом** (пункты 1, 7).
- **Б2. Задачи и заявки** (пункты 3, 4).
- **Б3. Документооборот** (пункт 2).
- **Б4. Отчётность** (пункт 6).
- **Сквозные качества** (пункты 5, 8) — нефункциональные требования, относящиеся ко всем блокам.

Дефекты исходных формулировок типичны: нет числовых критериев («быстро», «не тормозит»), не названы данные и роли («свои», «удобный»), не заданы условия выполнения. Ни одно требование в исходном виде непригодно для разработки и тестирования.

## 4. Стандартизированные требования

Для каждого блока указан стандарт, по которому выполнена стандартизация.

### Блок Б1. Управление пользователями и доступом
*(стандарты: ISO/IEC/IEEE 29148 — форма; FURPS+ — отнесение к F и «+»)*

1. Система должна хранить учётную запись сотрудника: ФИО, должность, подразделение, роль (сотрудник / руководитель / администратор).
2. Доступ в систему должен предоставляться только после аутентификации по логину и паролю; пароль хранится в виде хеша.
3. Обработка персональных данных сотрудников (ФИО, должность) должна вестись в соответствии с ФЗ-152 «О персональных данных».

### Блок Б2. Задачи и заявки
*(стандарты: ISO/IEC/IEEE 29148 — форма; FURPS+ — F)*

4. Руководитель должен иметь возможность создать заявку, указав исполнителя, срок и описание работ.
5. Заявка должна проходить цепочку согласования: «создана» → «на согласовании» → «утверждена» / «отклонена»; каждый переход фиксируется с датой и автором.
6. Руководитель должен видеть список задач подразделения с фильтрацией по исполнителю и статусу.

### Блок Б3. Документооборот
*(стандарты: ISO/IEC/IEEE 29148 — форма; FURPS+ — F, P)*

7. Система должна хранить документы с атрибутами: название, тип, автор, дата, связанная заявка.
8. Поиск документа по атрибутам и полному тексту должен выполняться не более чем за 1 секунду при базе до 100 000 документов.

### Блок Б4. Отчётность
*(стандарты: ISO/IEC/IEEE 29148 — форма; FURPS+ — F)*

9. Система должна формировать отчёт о загрузке сотрудников и ходе заявок за произвольно выбранный период с выгрузкой в Excel.

### Сквозные нефункциональные требования
*(стандарты: ГОСТ Р ИСО/МЭК 25010-2015 — характеристики качества; FURPS+ — U, P)*

10. Отклик интерфейса на действия пользователя — не более 0,5 секунды при одновременной работе до 100 сотрудников (производительность, time behaviour).
11. Интерфейс — на русском языке; освоение типовых операций новым сотрудником без обучения — не более 1 часа (удобство использования, operability).
12. Система должна работать в актуальных версиях браузеров Chrome, Edge и Firefox (совместимость, co-existence).

## 5. Обоснование результатов и вывод

Все восемь исходных пунктов сохранены по смыслу, но приведены к проверяемому виду: «быстро находить» → поиск ≤ 1 с при заданном объёме (п. 8), «не тормозит» → отклик ≤ 0,5 с при 100 пользователях (п. 10), «только для своих» → аутентификация и хеширование паролей (п. 2), «удобный интерфейс» → измеримое время освоения (п. 11). При этом анализ по FURPS+ и ГОСТ 25010 вскрыл пробелы исходного списка: не было требований надёжности (резервное копирование) и сопровождаемости (логирование) — их необходимо запросить у заказчика отдельно.

**Вывод:** изучены стандарты ISO/IEC/IEEE 29148, ГОСТ Р ИСО/МЭК 25010-2015 и модель FURPS+; на примере ПО для автоматизации бизнес-процессов выполнены анализ исходных требований, выделение четырёх функциональных блоков и стандартизация требований. Итоговый документ содержит 12 пронумерованных требований, для каждого блока указан применённый стандарт; каждое требование стало однозначным и проверяемым, то есть пригодным для разработки и тестирования.
