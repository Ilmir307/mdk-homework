## 1. Цель работы

Освоить работу с системой контроля версий Git и научиться применять стандарты кодирования PEP 8 при написании кода на Python.

## 2. Список использованных команд Git

| Команда | Назначение |
|---|---|
| `git init -b main` | Создать локальный репозиторий, основная ветка — main |
| `git status` | Посмотреть состояние файлов (что изменено, что в индексе) |
| `git add main.py` | Добавить файл в индекс (подготовить к коммиту) |
| `git commit -m "..."` | Зафиксировать изменения с осмысленным сообщением |
| `git log --oneline` | Просмотреть историю коммитов в кратком виде |
| `gh repo create MyRepository --public --source=. --push` | Создать удалённый репозиторий на GitHub и отправить в него локальную историю |
| `git push` | Отправить последующие коммиты в удалённый репозиторий |

## 3. Внесённые изменения

Файл `main.py` создан и изменён двумя коммитами:

```text
bafc137 Добавлены функции subtract и multiply, константы APP_NAME и VERSION, docstring

```

1. **Первый коммит:** простейший код — функция `add(a, b)` и её вызов.
2. **Второй коммит:** добавлены функции `subtract` и `multiply`, переменные-константы `APP_NAME` и `VERSION`, строки документации (docstring) модулю и функциям, точка входа `main()`.

## 4. Проверка соответствия PEP 8

Проверка выполнена двумя инструментами.

**pycodestyle** (проверка оформления по PEP 8):

```text
$ python -m pycodestyle main.py
(вывод пустой — нарушений не найдено)
```

**Pylint** (статический анализ качества кода):

```text
Your code has been rated at 10.00/10
```

Код изначально писался по стандартам, поэтому исправления не потребовались: имена функций в snake_case, константы в UPPER_CASE, двойные пустые строки между функциями, у каждой функции есть docstring, строки короче 79 символов.

## 6. Вывод

Создан репозиторий Git и одноимённый удалённый репозиторий на GitHub, в файл `main.py` внесены изменения в два коммита с осмысленными сообщениями. Итоговый код проверен инструментами pycodestyle и Pylint: нарушений PEP 8 не выявлено (оценка Pylint 10.00/10), программа запускается и работает корректно. Работа показала основной цикл Git: изменение → `git add` → `git commit` → `git push` — с возможностью в любой момент посмотреть историю через `git log`.
