# Анализ и применение стандартов кодирования в системах контроля версий

**МДК 02.02 · группа 3424А**
**Репозиторий:** [github.com/Ilmir307/pep8-versioned-demo](https://github.com/Ilmir307/pep8-versioned-demo) (тег версии `v1.0`)
**Презентация:** [1875-prezentaciya-pep8.pptx](1875-prezentaciya-pep8.pptx) (5 слайдов)

## 1. Цель работы

Изучить стандарт PEP 8 и применить его в работе с системой контроля версий Git на примере Python-скрипта.

## 2. Выполненная работа

1. Создан репозиторий Git `pep8-versioned-demo` и настроен для проекта.
2. Написан скрипт [factorial_script.py](https://github.com/Ilmir307/pep8-versioned-demo/blob/main/factorial_script.py) — вычисление факториалов чисел от 0 до 7.
3. Код сразу оформлен по PEP 8; проверка `pycodestyle` нарушений не выявила.
4. Изменения зафиксированы коммитом с осмысленным сообщением.
5. Создан аннотированный тег версии: `git tag -a v1.0 -m "Версия 1.0: вычисление факториала"`, тег отправлен на GitHub (`git push --tags`).

## 3. Применённые правила PEP 8 и их влияние на код

| Правило | Как применено | Влияние на читаемость |
|---|---|---|
| Имена в snake_case | `factorial`, `main` | Функцию легко найти и произнести |
| Docstring у модуля и функций | Каждая функция документирована | Назначение понятно без чтения кода |
| Отступы 4 пробела | Во всех блоках | Единая визуальная структура |
| Строки ≤ 79 символов | Соблюдено | Код читается без горизонтальной прокрутки |
| Защита `if __name__ == "__main__":` | Точка входа отделена | Скрипт можно импортировать без побочных запусков |

Поскольку стандарт применялся с первой строки, «исправлений» почти не потребовалось — в этом и польза: соблюдение PEP 8 при написании дешевле, чем последующий рефакторинг.

## 4. Как стандарты помогают в совместной работе

Единый стиль снимает целый класс конфликтов в команде: ревьюер обсуждает логику, а не оформление; автоматическая проверка линтером делает стандарт объективным; теги версий в Git связывают стандарты с релизным процессом — любое состояние кода можно вернуть по тегу. Подробности — в приложенной презентации.

## 5. Вывод

Стандарт PEP 8 применён к Python-скрипту внутри реального Git-рабочего процесса: репозиторий, коммит, тег версии v1.0, публикация на GitHub. Проверка инструментом подтвердила соответствие стандарту, а тег зафиксировал стабильную версию проекта. Связка «стандарт + контроль версий» превращает качество кода из пожелания в проверяемое свойство каждого коммита.
