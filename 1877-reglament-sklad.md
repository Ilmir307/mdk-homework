# Регламент взаимодействия в команде разработчиков

**Проект: информационная система для управления складом · МДК 02.02 · группа 3424А**

## 1. Назначение регламента

Регламент определяет правила совместной работы команды: распределение обязанностей, коммуникационные каналы, процедуры разработки, работу с контролем версий и систему отчётности. Документ обязателен для всех участников проекта.

## 2. Роли и обязанности

| Роль | Обязанности |
|---|---|
| Менеджер проекта | План, сроки, бюджет, связь с заказчиком, эскалации |
| Аналитик | Требования, ТЗ, уточнение складских процессов у заказчика |
| Ведущий разработчик | Архитектура, код-ревью, технические стандарты |
| Разработчики | Реализация модулей, модульные тесты |
| Тестировщики | Тест-сценарии, проверка, регистрация дефектов |

## 3. Коммуникационные каналы

| Канал | Назначение | Регламент |
|---|---|---|
| Стендап | Статус и препятствия | Ежедневно, 15 минут |
| Планёрка | Приоритеты недели | Понедельник, 40 минут |
| Telegram-чат | Оперативные вопросы | Ответ ≤ 1 часа в рабочее время |
| Таск-трекер | Статусы задач | Обновление ежедневно |
| Wiki | ТЗ, решения, регламенты | Актуализация по факту изменений |

## 4. Процедуры совместной работы

**Этап разработки:** задача берётся из трекера только из колонки «готово к разработке»; разработчик создаёт ветку, реализует, пишет модульные тесты. **Этап тестирования:** задача переходит тестировщику только с пометкой разработчика «готово к проверке»; найденный дефект возвращается с шагами воспроизведения. **Этап внедрения:** в релиз входит только код, прошедший ревью и тесты; внедрение выполняет ведущий разработчик совместно с менеджером проекта, после внедрения — инструктаж кладовщиков.

## 5. Правила работы с Git

- `main` защищена: изменения только через pull request.
- Ветка на задачу: `feature/<номер>-<тема>`; сообщения коммитов осмысленные.
- Слияние — после код-ревью ведущего разработчика и зелёных автотестов.
- Код соответствует PEP 8, проверка линтером до PR.
- Релизы помечаются тегами версий.

## 6. Отчётность и контроль выполнения задач

- **Ежедневно:** статус задач на доске + стендап.
- **Еженедельно:** менеджер проекта готовит сводку заказчику: закрытые задачи, отставания, риски.
- **Контрольные точки этапов:** выход с этапа — только при выполнении Definition of Done (код + тесты + ревью + документация).
- **Отставание более 2 дней** — автоматический разбор на планёрке с перераспределением задач.

## 7. Вывод

Регламент взаимодействия для проекта ИС управления складом определяет роли, каналы связи с нормами ответа, процедуры по этапам «разработка–тестирование–внедрение», правила Git и систему отчётности с контрольными точками. Документ написан понятным всем участникам языком и сам версионируется вместе с проектом: изменения регламента проходят через ретроспективу и фиксируются новой версией.
