# Разработка и настройка системы непрерывной интеграции для проекта на Python

**МДК 02.02 · группа 3424А**
**Репозиторий:** [github.com/Ilmir307/python-ci-cd-demo](https://github.com/Ilmir307/python-ci-cd-demo)
**Успешный прогон GitHub Actions:** [CI run #40930497279](https://github.com/Ilmir307/python-ci-cd-demo/actions/runs/40930497279)

## 1. Цель работы

Разработать и настроить систему непрерывной интеграции (CI/CD) для проекта на Python с использованием Jenkins и GitHub Actions: автоматизировать сборку, тестирование и развёртывание.

## 2. Проект

Создан репозиторий `python-ci-cd-demo` на GitHub с простым веб-приложением на Python (`app.py` — HTTP-сервер, отвечает «Hello, World!») и модульным тестом `test_app.py`.

## 3. Настройка Jenkins

Jenkins устанавливается в Docker-контейнере или из WAR-файла (требуется Java 17+). После установки и начальной разблокировки создаётся проект типа **Pipeline** с источником «Pipeline script from SCM»: указывается URL репозитория на GitHub и ветка `main`. Сценарий пайплайна хранится в репозитории — файл [Jenkinsfile](https://github.com/Ilmir307/python-ci-cd-demo/blob/main/Jenkinsfile):

| Стадия | Содержимое |
|---|---|
| Сборка | `python -m py_compile app.py test_app.py` — компиляция, проверка синтаксиса |
| Тестирование | `python -m unittest test_app.py -v` — модульный тест |
| Развёртывание | копирование приложения в каталог тестового сервера |

Автоматический запуск при изменении кода настраивается триггером «Poll SCM» (например, `H/5 * * * *`) или webhook от GitHub.

## 4. Настройка GitHub Actions

В репозитории создан файл [.github/workflows/ci.yml](https://github.com/Ilmir307/python-ci-cd-demo/blob/main/.github/workflows/ci.yml). Конвейер запускается автоматически при каждом `push` и pull request и выполняет шаги:

1. **checkout** — получение кода репозитория;
2. **setup-python** — установка Python 3.12 на раннер Ubuntu;
3. **сборка** — `python -m py_compile app.py test_app.py`;
4. **проверка стиля** — установка и запуск pycodestyle (PEP 8);
5. **тестирование** — `python -m unittest test_app.py -v`.

## 5. Тестирование настроенной системы

После коммита и push конвейера GitHub Actions система сработала автоматически: запуск [CI #40930497279](https://github.com/Ilmir307/python-ci-cd-demo/actions/runs/40930497279) завершился со статусом **success** за 17 секунд — сборка, проверка PEP 8 и модульный тест прошли без ошибок. Статус прогона виден зелёной отметкой у коммита в репозитории (это и есть «скриншот» результата — страница прогона публична).

## 6. Выводы

Для Python-проекта настроены две CI-схемы: Jenkins (Jenkinsfile в репозитории, пайплайн «сборка → тесты → развёртывание», триггер по изменению кода) и GitHub Actions (workflow с проверкой синтаксиса, стиля и тестами). Система GitHub Actions проверена в действии: прогон при push завершился успешно. Непрерывная интеграция гарантирует, что каждая версия кода автоматически собирается и тестируется — ошибки обнаруживаются сразу, а не в момент релиза. GitHub Actions проще в старте (не нужен свой сервер), Jenkins гибче и подходит для закрытого контура компании.
