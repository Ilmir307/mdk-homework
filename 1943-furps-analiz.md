# Анализ требований с использованием модели FURPS+

**МДК 02.02 · группа 3424А**

## 1. Цель работы

Изучить компоненты модели FURPS+ (Functionality, Usability, Reliability, Performance, Supportability) и применить их для анализа требований к программному продукту: определить, какие компоненты применимы к каждому требованию, и сформулировать характеристики для оценки.

## 2. Таблица анализа требований

| № | Требование | Компонент FURPS+ | Характеристики и параметры для оценки |
|---:|---|---|---|
| 1 | Регистрация пользователей | Functionality (+ «+» для ПДн) | Данные: логин, e-mail, пароль; валидация e-mail; пароль ≥ 8 символов в виде хеша; время регистрации ≤ 1 с; обработка ПДн по ФЗ-152 |
| 2 | Доступ к информации о пользователях | Functionality + Reliability | Разграничение прав (пользователь видит своё, администратор — всё); журнал обращений к данным; корректность выдачи 100 % |
| 3 | Поиск информации по ключевым словам | Functionality + Performance | Полнотекстовый индекс; время поиска ≤ 1 с при 100 000 записей; ранжирование по релевантности |
| 4 | Работа с несколькими языками | Usability | Состав языков (русский, английский); переключение без перезапуска; внешние файлы строк без правки кода |
| 5 | Доступность с мобильных устройств | Usability + Performance | Адаптивная вёрстка от 360 px; загрузка главной страницы по 4G ≤ 3 с; элементы управления ≥ 48×48 dp |

## 3. Пояснения к выбору компонентов

- Требования 1–3 описывают функции системы — это **Functionality**; при этом доступ к чужим данным (2) и поиск со скоростью (3) вытягивают за собой нефункциональные характеристики Reliability и Performance.
- Требования 4 и 5 про удобство для пользователя — **Usability**; мобильная доступность добавляет параметр скорости на слабом канале (Performance).
- Каждое требование снабжено измеримыми параметрами, чтобы его можно было проверить при тестировании.

## 4. Вывод

Пять требований к продукту проанализированы по модели FURPS+: определены применимые компоненты (F для всех, плюс R, P, U для отдельных требований) и сформулированы характеристики оценки. Анализ показал, что даже простые с виду функциональные требования («доступ к информации», «поиск») немедленно порождают нефункциональные требования к правам доступа и скорости — модель FURPS+ заставляет учесть их сразу, а не на этапе тестирования.
