# Анализ производительности и поиск утечек памяти с использованием Valgrind и gcov

**МДК 02.02 · группа 3424А**

## 1. Использованные инструменты

Задание предполагает Valgrind и gcov — инструменты для программ на C/C++ под Linux (Valgrind анализирует память машинного кода, gcov — покрытие скомпилированного кода). Для **Python под Windows** они неприменимы напрямую, поэтому использованы функциональные аналоги из экосистемы Python с той же методикой «замер → исправление → контрольный замер»:

- **tracemalloc** (стандартная библиотека) — учёт выделенной памяти, аналог поиска утечек Valgrind;
- **ResourceWarning** (`python -W always`) — обнаружение незакрытых файловых дескрипторов;
- **coverage** — покрытие кода при выполнении, аналог gcov.

**Анализируемый скрипт:** [task1603_leaky.py](task1603_leaky.py) — обработка данных с тремя проблемами: бесконтрольно растущий глобальный кэш, незакрытый файл, мёртвая функция. Замеры выполняет [task1603_measure.py](task1603_measure.py) (20 раундов по 1000 значений).

## 2. Результаты первичного анализа

**Память (tracemalloc):**

```text
С утечкой (глобальный кэш): 56.1 МБ
```

**Незакрытый файл (ResourceWarning):**

```text
ResourceWarning: unclosed file <_io.TextIOWrapper name='task1603-log.txt' ...>
```

**Покрытие (coverage):**

```text
Name                Stmts   Miss  Cover   Missing
task1603_leaky.py       9      1    89%   24
```

**Выявленные проблемы:** (1) глобальный список `CACHE` растёт без ограничений — 56,1 МБ за прогон; (2) файл открыт без `with` и не закрывается — утечка дескриптора; (3) функция `unused_branch` (строка 24) никогда не выполняется — покрытие 89 %.

## 3. Внесённые изменения

Файл [task1603_fixed.py](task1603_fixed.py):

1. Кэш ограничен константой `CACHE_LIMIT = 100`: при превышении старые записи удаляются — память перестаёт расти с числом вызовов.
2. Файл открывается через `with` — закрытие гарантировано.
3. Мёртвая функция удалена.

## 4. Контрольный анализ после исправлений

```text
После исправления (лимит кэша): 0.293 МБ
Записей в кэше после исправления: 100 (лимит: 100)

task1603_fixed.py       9      0   100%
```

| Метрика | До | После | Улучшение |
|---|---|---|---|
| Память после 20 раундов | 56,1 МБ | 0,293 МБ | в 191 раз |
| ResourceWarning (незакрытый файл) | есть | нет | устранено |
| Покрытие кода | 89 % | 100 % | мёртвый код устранён |

## 5. Выводы

Применена методика анализа в стиле Valgrind/gcov средствами Python: найдены утечка памяти (неконтролируемый глобальный кэш), утечка файлового дескриптора (файл без `with`) и непокрытый код. После исправлений потребление памяти снизилось в 191 раз, предупреждения о дескрипторах исчезли, покрытие достигло 100 %. Главный вывод: «утечки» возможны и в языке со сборкой мусора — через неявные долгоживущие ссылки (глобальные коллекции) и внешние ресурсы (файлы); инструменты профилирования и покрытия выявляют их измеримо.
