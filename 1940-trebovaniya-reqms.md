# Документ требований: система управления требованиями

**МДК 02.02 · группа 3424А**

## 1. Введение

Документ содержит требования к системе управления требованиями (ReqMS) — веб-приложению для сбора, классификации и трассировки требований в проектах разработки. Требования сформулированы по модели FURPS+ и проверены по ISO/IEC/IEEE 29148 (однозначность, полнота, проверяемость) и ГОСТ Р ИСО/МЭК 25010-2015 (полнота характеристик качества). Для проекта наиболее важны компоненты F (ядро — работа с требованиями), R (требования — ценные данные) и S (система расширяется шаблонами отчётов).

## 2. Функциональные требования

| № | Требование | Приоритет | Зависимости |
|---:|---|---|---|
| F1 | Создание требования: текст, тип, источник, критерий приёмки | Must | — |
| F2 | Классификация требования по компонентам FURPS+ | Must | F1 |
| F3 | Версии требования: история изменений с автором и датой | Must | F1 |
| F4 | Трассировка: связи «требование → тест / задача» | Should | F1 |
| F5 | Отчёт-спецификация (экспорт в Markdown/CSV) | Should | F1, F2 |
| F6 | Поиск и фильтры по типу, приоритету, статусу | Should | F1 |
| F7 | Совместное редактирование с блокировкой версии | Could | F3 |

Приоритеты заданы по MoSCoW (Must/Should/Could/Won't сейчас); зависимости показывают, какие требования опираются на другие.

## 3. Нефункциональные требования

| № | Компонент | Требование |
|---:|---|---|
| U1 | Usability | Создание требования — не более 5 полей обязательного ввода; интерфейс на русском |
| R1 | Reliability | Ни одно изменение требования не теряется: все версии хранятся; резервное копирование ежедневно |
| R2 | Reliability | Доступность системы ≥ 99,5 % рабочего времени |
| P1 | Performance | Открытие списка из 5 000 требований ≤ 2 с; поиск ≤ 1 с |
| S1 | Supportability | Шаблоны отчётов и перечни типов настраиваются без смены кода; покрытие тестами ≥ 70 % |

## 4. Ограничения и предположения

- **ОГР1.** Персональные данные пользователей системы — по ФЗ-152.
- **ОГР2.** Реализация: Python + PostgreSQL, развёртывание в контуре заказчика.
- **П1.** Предполагается команда до 50 аналитиков одновременно.
- **П2.** Интеграция с Jira — вне рамок версии 1.0 (учтена как Could на будущее).

## 5. Анализ документа на соответствие стандартам

Проверка по ISO/IEC/IEEE 29148: каждое требование имеет идентификатор, однозначную формулировку и (для нефункциональных) числовой критерий. По FURPS+: заняты все компоненты, «бесхозных» требований нет. По ГОСТ 25010: покрыты функциональная пригодность, удобство, надёжность, производительность, сопровождаемость. Приоритеты и зависимости заданы явно, что делает документ пригодным для планирования релизов.

## 6. Вывод

Разработан документ требований к системе управления требованиями: 7 функциональных и 5 нефункциональных требований с приоритетами MoSCoW и зависимостями, ограничения и предположения, анализ соответствия стандартам. Документ пригоден как основа технического задания и план спринтов: Must-требования F1–F3 образуют первый инкремент.
