# Анализ и классификация инструментальных средств разработки ПО

**МДК 02.02 · группа 3424А**

## 1. Цель работы

Изучить и классифицировать инструментальные средства разработки ПО по категориям: IDE (Visual Studio Code, PyCharm, Jupyter Notebook), СКВ (Git, GitHub), CASE-средства (IBM Rational Rose, Oracle Designer), инструменты автоматизации сборки (Jenkins, TeamCity).

## 2. Таблица характеристик

| Инструмент | Тип | Основные функции | Пример использования | Преимущества | Недостатки |
|---|---|---|---|---|---|
| Visual Studio Code | IDE | Редактор кода, отладка, расширения, встроенный Git | Разработка на Python, веб-проекты | Бесплатный, лёгкий, огромная экосистема расширений | Требует настройки под язык, уступает полным IDE в анализе кода |
| PyCharm | IDE | Умный анализ Python-кода, рефакторинг, отладчик, тесты | Профессиональная разработка на Python | Глубокая поддержка Python из коробки | Pro-версия платная, требователен к ресурсам |
| Jupyter Notebook | IDE (интерактивная) | Блоки кода с немедленным выполнением, визуализация данных | Анализ данных, обучение, эксперименты | Наглядность, интерактивность | Не для полноценных приложений, слабый контроль версий |
| Git | СКВ | История изменений, ветки, слияния, локальная работа | Версионирование любого проекта | Быстрый, распределённый, стандарт отрасли | Порог входа (консоль, концепция ветвления) |
| GitHub | СКВ (хостинг) | Хостинг репозиториев, pull request, Issues, Actions | Совместная разработка, код-ревью | Популярность, бесплатные публичные репозитории | Зависимость от облачного сервиса |
| IBM Rational Rose | CASE | UML-моделирование, генерация кода по моделям | Проектирование архитектуры по UML | Полная поддержка UML своего времени | Устарел, сложен, дорогой |
| Oracle Designer | CASE | Моделирование БД (ER), генерация схем Oracle | Проектирование баз данных под Oracle | Тесная связь с СУБД Oracle | Привязка к Oracle, устаревший интерфейс |
| Jenkins | Автоматизация сборки | CI/CD-конвейеры, автосборка, тесты, развёртывание | Непрерывная интеграция коммитов | Бесплатный, сотни плагинов | Нужен свой сервер и сопровождение |
| TeamCity | Автоматизация сборки | CI/CD, управление агентами, отчёты о тестах | Корпоративные сборки | Удобная настройка, качественный UI | Платный при масштабировании |

## 3. Схема взаимодействия инструментов

```mermaid
flowchart LR
    A[IDE<br>VS Code / PyCharm] -->|коммит, push| B[СКВ<br>Git / GitHub]
    B -->|событие push| C[Автоматизация сборки<br>Jenkins / TeamCity]
    C -->|сборка, тесты, отчёт| D[Сборка и развёртывание]
    C -->|статус сборки| B
    E[CASE<br>Rational Rose / Oracle Designer] -.->|модели и схемы БД<br>на этапе проектирования| A
```

IDE передаёт код в СКВ; событие в СКВ запускает конвейер автоматизации сборки, результат возвращается статусом в репозиторий; CASE-средства обслуживают этап проектирования и передают модели разработчикам в IDE.

## 4. Вывод

Девять инструментов классифицированы по четырём категориям; для каждого описаны функции, примеры использования, преимущества и недостатки. Схема взаимодействия показывает, что инструменты работают как единая цепочка: проектирование (CASE) → кодирование (IDE) → версии и совместная работа (СКВ) → сборка и поставка (автоматизация). Для учебного Python-проекта достаточно связки VS Code + Git/GitHub + Jenkins; Jupyter подключается для экспериментов с данными.
