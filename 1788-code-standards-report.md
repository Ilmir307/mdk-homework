# Анализ и применение стандартов кодирования в системах контроля версий

**МДК 02.02 · группа 3424А**
**Репозиторий:** [github.com/Ilmir307/code-standards-demo](https://github.com/Ilmir307/code-standards-demo)

## 1. Цель работы

Изучить стандарты кодирования и их применение в системе контроля версий: проанализировать существующий код, выявить нарушения стандартов и исправить их с фиксацией изменений в Git.

**Использованные стандарты и инструменты:** PEP 8 (соглашения об именовании, отступах, пробелах, документации), анализатор Pylint 4.0.9, система контроля версий Git + GitHub.

## 2. Исходный код и выявленные нарушения

В репозиторий помещены два файла с намеренными нарушениями: `orders.py` и `discount.py` (коммит «Исходный код с нарушениями стандартов кодирования»). Анализ Pylint выявил нарушения, оценка — **0.00/10**. Полный лог: [1788-pylint-log.txt](1788-pylint-log.txt). Основные группы нарушений:

| № | Код | Нарушение | Исправление |
|---|---|---|---|
| 1 | C0103 | Имена класса, функций, аргументов не по соглашениям (`order`, `GetTotal`, `Id`, `Percent`) | Класс — PascalCase (`Order`), функции и аргументы — snake_case (`get_total`, `order_id`, `percent`) |
| 2 | W0311 | Отступы в 2 пробела вместо 4 | Отступы приведены к 4 пробелам |
| 3 | C0114/C0116 | Нет строк документации у модуля и функций | Добавлены docstring |
| 4 | W0612 | Неиспользуемая переменная `temp_variable` | Переменная удалена |
| 5 | R0903 | У класса один публичный метод | Добавлен полезный метод `apply_discount` |
| 6 | — | Код на верхнем уровне без защиты | Точка входа обёрнута в `if __name__ == "__main__":` |

## 3. Исправление и фиксация в Git

Нарушения исправлены в обоих файлах (логика работы сохранена: программы выводят те же результаты «Заказ 1 на сумму 500» и «Цена со скидкой: 900.0»). Изменения зафиксированы отдельным коммитом; история репозитория:

```text
b2a17fa Исправлены нарушения стандартов: имена snake_case/PascalCase, docstring, отступы, удалена неиспользуемая переменная
cf560c8 Исходный код с нарушениями стандартов кодирования
```

Повторный анализ Pylint после исправлений:

```text
Your code has been rated at 10.00/10 (previous run: 0.00/10, +10.00)
```

## 4. Вывод

Проведён анализ кода инструментом Pylint в рамках работы с Git: выявлено 16 нарушений стандартов кодирования (именование, отступы, документация, неиспользуемый код), все исправлены; оценка выросла с 0.00/10 до 10.00/10. Фиксация «нарушающего» и «исправленного» состояний отдельными коммитами оставляет в истории репозитория весь путь приведения кода к стандартам — это и есть практический смысл связки «линтер + Git».
