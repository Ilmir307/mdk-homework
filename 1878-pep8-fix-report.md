# Анализ и применение стандартов кодирования в системах контроля версий

**МДК 02.02 · группа 3424А**
**Репозиторий:** [github.com/Ilmir307/pep8-fix-demo](https://github.com/Ilmir307/pep8-fix-demo)

## 1. Цель работы

Проанализировать существующий код, выявить нарушения стандартов кодирования (PEP 8), внести исправления и зафиксировать процесс в системе контроля версий Git.

## 2. Анализ исходного кода

Файл `weather.py` (коммит «Исходный код weather.py с нарушениями PEP 8») проверен инструментами **pycodestyle** и **Pylint**; оценка Pylint — **0.00/10**. Лог pycodestyle: [1878-pycodestyle-log.txt](1878-pycodestyle-log.txt).

Выявленные нарушения и обоснование исправлений:

| № | Код | Нарушение | Почему исправлено |
|---|---|---|---|
| 1 | E111 | Отступы в 2 пробела | PEP 8 требует 4 пробела — единый отступ читается одинаково у всех |
| 2 | E225 | Нет пробелов вокруг `=` | Пробелы отделяют операторы, код не сливается |
| 3 | E231 | Нет пробела после запятой | Аргументы читаются по отдельности |
| 4 | E305 | После функции одна пустая строка | Два пустых ряда визуально завершают определение |
| 5 | C0103 (Pylint) | `Get_weather` вместо snake_case | Единое именование функций в проекте |
| 6 | W0612 (Pylint) | Неиспользуемая переменная `Unused_result` | Мёртвый код вводит в заблуждение |
| 7 | C0114/C0116 (Pylint) | Нет docstring у модуля и функции | Документация объясняет назначение без чтения кода |
| 8 | — | URL собирался внутри функции из литерала | Адрес API вынесен в константу `API_URL` (UPPER_CASE) — конфигурация не «зашита» в логику |

## 3. Исправление и фиксация в Git

Исправленный файл сохраняет поведение программы (проверено запуском: печатает тот же URL). Проверка после исправлений: pycodestyle — нарушений нет, Pylint — **10.00/10**. Изменения зафиксированы отдельным коммитом:

```text
8904e6a Исправлены нарушения PEP 8: отступы, пробелы, имена, удалена неиспользуемая переменная
f190733 Исходный код weather.py с нарушениями PEP 8
```

## 4. Вывод

Проведён анализ кода двумя инструментами: pycodestyle нашёл 12 нарушений оформления, Pylint добавил нарушения именования, неиспользуемую переменную и отсутствие документации. Все нарушения исправлены с обоснованием каждого изменения; оценка выросла с 0.00/10 до 10.00/10. Раздельные коммиты «до» и «после» сохраняют в Git весь путь приведения кода к стандартам.
