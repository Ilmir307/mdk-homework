# Анализ и сравнение инструментальных средств разработки ПО

**МДК 02.02 · группа 3424А**

## 1. Цель работы

Изучить и сравнить основные инструментальные средства разработки ПО: интегрированную среду разработки (на примере PyCharm), систему контроля версий (Git), систему непрерывной интеграции (Jenkins) и средство статического анализа кода (Pylint).

## 2. Основные характеристики инструментов

- **PyCharm (IDE).** Среда разработки для Python: редактор с автодополнением, отладчик, рефакторинг, запуск тестов. Решает задачу продуктивного написания и отладки кода.
- **Git (СКВ).** Распределённый контроль версий: история изменений, ветки, слияния. Решает задачу хранения версий и параллельной работы команды.
- **Jenkins (CI/CD).** Сервер непрерывной интеграции: автоматическая сборка, тестирование и развёртывание при каждом изменении кода. Решает задачу автоматизации рутинных проверок и поставки.
- **Pylint (статический анализ).** Анализ кода без запуска: проверка стандартов (PEP 8), поиск неиспользуемых переменных, потенциальных ошибок. Решает задачу контроля качества кода до запуска.

## 3. Таблица сравнения

| Параметр | PyCharm | Git | Jenkins | Pylint |
|---|---|---|---|---|
| Категория | IDE | СКВ | CI/CD | Статический анализ |
| Поддерживаемые языки | Python (Pro: +веб-языки) | Любые (текстовые файлы) | Любые (через скрипты) | Только Python |
| Возможности отладки | Полноценный отладчик | Нет | Нет (только лог сборки) | Нет (анализ без запуска) |
| Интеграция с СКВ | Встроенная (Git и др.) | Сам является СКВ | Выкачивает код из Git по событию | Запускается в CI-конвейере |
| Интеграция с другими инструментами | Git, Docker, БД, pytest | GitHub, IDE, CI-серверы | Git, Docker, любые скрипты | IDE, pre-commit, Jenkins |
| Этап жизненного цикла | Кодирование и отладка | Все этапы | Сборка, тестирование, поставка | Контроль качества кода |
| Стоимость | Community бесплатно / Pro платно | Бесплатен | Бесплатен | Бесплатен |

## 4. Интеграция инструментов между собой

Инструменты образуют цепочку: разработчик пишет код в **PyCharm**, фиксирует его в **Git** (коммит и push), событие в репозитории запускает конвейер **Jenkins**, одним из шагов которого является проверка **Pylint**; при нарушениях сборка помечается неуспешной, и код не попадает дальше. Также Pylint встроен в PyCharm (подсветка проблем прямо в редакторе) и может запускаться как pre-commit hook в Git.

## 5. Примеры использования в реальных проектах

- **PyCharm** — разработка серверной части веб-сервисов (Django/Flask-проекты).
- **Git + GitHub** — совместная разработка open-source проектов (Linux, CPython) с тысячами участников.
- **Jenkins** — ночные сборки и регрессионное тестирование в корпоративных проектах.
- **Pylint** — обязательная проверка стиля в командных проектах на Python (в т. ч. в учебном репозитории этой работы — оценка 10.00/10).

## 6. Вывод

Наибольшую эффективность даёт не выбор одного «самого сильного» инструмента, а их сочетание: IDE ускоряет написание кода, СКВ делает работу команды безопасной, CI/CD автоматизирует проверки и поставку, статический анализатор удерживает качество кода. Для Python-проекта разумный минимум — связка PyCharm + Git + Pylint; при росте команды к ней добавляется Jenkins или аналогичный CI-сервер.
